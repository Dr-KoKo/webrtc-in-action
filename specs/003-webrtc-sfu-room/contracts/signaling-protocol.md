# SFU Signaling Protocol Contract (v3)

**Feature**: SFU Learning Room (003)
**Branch**: `003-webrtc-sfu-room`
**Contract version**: `3`
**Date**: 2026-05-03
**Transport**: WebSocket text frames at `/ws/sfu` (one JSON message per frame)
**Status**: **canonical source of truth** for every SFU-mode signaling
message. The Go server (`signaling/internal/modes/sfu/protocol/`) and
the TypeScript client (`frontend/src/modes/sfu/protocol/`) derive their
validators from this document.

> Per Constitution Principle II + Governance G-3: **no ad-hoc JSON
> messages are permitted.** Any message whose `type` is not listed
> below, or whose shape does not match its schema here, MUST be
> rejected by both sides with an `error { code: "malformed" }` log
> entry.

> **001 v1 contract is unaffected.** The 001 contract at
> `specs/001-webrtc-1to1-call/contracts/signaling-protocol.md` (`v: 1`)
> is the canonical contract for `/ws` and is **not edited** by this
> document.

> **002 v2 contract is unaffected.** The 002 contract at
> `specs/002-webrtc-mesh-room/contracts/signaling-protocol.md` (`v: 2`)
> is the canonical contract for `/ws/mesh` and is **not edited** by
> this document.

> v3 is **additive**: a new endpoint, a new envelope version, new
> message types. v3 MUST NOT reuse v1 or v2 message types in a way
> that changes their semantics. v1/v2 messages MUST NOT appear on
> `/ws/sfu`; v3 messages MUST NOT appear on `/ws` or `/ws/mesh`
> (FR-021, FR-090 (e)).

---

## 1. Message envelope

Every frame on `/ws/sfu` is a JSON object with the following envelope:

```json
{
  "v": 3,
  "type": "<enum>",
  "roomId": "<string, required for all room-scoped messages>",
  "from": "<participantId, set by server on relay>",
  "to": "<participantId, optional unicast target>",
  "requestId": "<uuid-v4, optional, for request correlation>",
  "ts": 1714688000000,
  "payload": { }
}
```

| Field | Type | Required | Notes |
|---|---|---|---|
| `v` | integer | **yes** | SFU contract version; currently `3`. v1/v2 reserved for 001/002. |
| `type` | string | **yes** | SFU message-type enum (see §3) |
| `roomId` | string | **yes** for room-scoped messages | validated per Room ID rules |
| `from` | string | server-set on relay | UUIDv4 participant ID |
| `to` | string | optional | set when relaying a unicast target |
| `requestId` | string | optional | UUIDv4 generated by sender of request-style messages |
| `ts` | integer | optional | Unix milliseconds; informational |
| `payload` | object | per-type | see each message below |

### 1.1 Room ID validation

Identical to 001 and 002 (FR-010 explicitly preserves the rule across
modes):

- trimmed of leading / trailing whitespace before validation;
- case-sensitive;
- length `1..64` after trimming;
- regex `^[A-Za-z0-9._-]{1,64}$`;
- any violation ⇒ `join_rejected` with
  `payload.result = "join_rejected_invalid_room"`.

### 1.2 Participant ID generation

Server generates a UUIDv4 on `join_accepted`. Clients MUST NOT invent
their own `participantId`.

### 1.3 SFU-room namespace separation

An SFU room and a 1:1 / mesh room may share the same `roomId` string
without collision because they are tracked in separate registries
reached via separate endpoints (`/ws` vs `/ws/mesh` vs `/ws/sfu`). No
cross-mode lookup is performed.

### 1.4 Transport-attempt scope (FR-090 (a))

- `transportAttemptId` is a `uint64` issued and incremented by the
  server when it kicks a renegotiation; the client mirrors this counter.
- Initial transport: `transportAttemptId = 1`.
- Subscriber add/remove: server sends `transport_renegotiation_needed
  { transportAttemptId: N+1, ... }`; client uses `N+1` as its next
  attempt.
- **Carried only on transport-negotiation messages** (offer, answer,
  ICE candidate, `transport_offer_requested`, `transport_renegotiation_needed`).
- **NEVER carried on participant- / track-level metadata** such as
  `media_state_update`, `published_track_*`, `subscribed_track_*`,
  `subscription_state_changed`, `forwarding_summary_update`,
  `learning_inspector_update`, `roster_*`, `participant_left`,
  `participant_released`, `sfu_status_changed`. Putting
  `transportAttemptId` on a metadata message is a `malformed` error.
- Stale messages (lower `transportAttemptId` than the current attempt)
  MUST be discarded before being applied (EC-009).

### 1.5 Wire payload restrictions (NFR-004, EC-016, SC-S08)

The v3 wire **MAY** carry:

- raw SDP offer/answer payloads on `transport_offer` / `transport_answer`
  (required for WebRTC negotiation; FR-090 (c));
- raw ICE candidate strings on `transport_ice_candidate` (same).

The v3 wire **MUST NOT** carry:

- raw RTP packets, raw RTP payloads, media payloads of any kind;
- TURN credentials (TURN URLs MAY appear without credentials in
  `iceServers`; the SFU never embeds passwords on the wire);
- chat message types (DD-003 = A);
- recording or persistence message types (Non-Goals);
- `screen_share_busy` (DD-004 = A); no room-level current-sharer
  concept exists.

Rendering / logging restrictions on the **client** (NFR-004):

- raw SDP, raw ICE candidate strings, TURN credentials, raw RTP, raw
  SSRC hex MUST NOT appear in the UI / event log / inspector / app
  logs. The contract permits transmission; the **client store** does
  the redaction (data-model §B.10, §B.11).

### 1.6 Direction legend

- **C→S**: client → server.
- **S→C**: server → client (unicast to one participant).
- **S→B**: server → broadcast (to multiple participants in the same SFU room).
- **C→S→B**: server fan-out (one client message → server fans out to
  all other room participants; used for `media_state_update`).

## 2. Version handshake

A frame on `/ws/sfu` carrying `v != 3` MUST receive
`error { code: "unsupported_version" }`. The server MUST NOT mutate
any room state on a version mismatch. The server MUST NOT auto-respond
with `join_accepted` or `join_rejected` for such a frame; admission
semantics apply only after envelope validation.

---

## 3. Message types

### 3.1 `join_room` (C→S)

**Purpose**: client requests admission to an SFU room.

**Required**: `v`, `type`, `roomId`, `requestId`. **Payload**: `{}`.

```json
{
  "v": 3,
  "type": "join_room",
  "roomId": "demo",
  "requestId": "5b3a1e23-...",
  "payload": {}
}
```

**Server validation**:

1. Envelope shape valid; `v == 3`.
2. `roomId` matches the regex (§1.1).
3. The SFU room has fewer than 4 reserved slots.
4. The source WebSocket is not already in any SFU room (`already_joined` if it is).

**Server response** (exactly one):

- `join_accepted` (admission OK), or
- `join_rejected` with `payload.result ∈ { "join_rejected_room_full",
  "join_rejected_invalid_room" }`, or
- `error { code: "already_joined" }`.

---

### 3.2 `join_accepted` (S→C)

**Purpose**: tell the joiner admission succeeded. Assigns
`participantId`, `admissionIndex`, `transportId`, and the ICE servers.

```json
{
  "v": 3,
  "type": "join_accepted",
  "roomId": "demo",
  "requestId": "5b3a1e23-...",
  "payload": {
    "participantId": "8e4c0...",
    "admissionIndex": 3,
    "transportId": "f7c11-...",
    "iceServers": [
      { "urls": ["stun:stun.l.google.com:19302"] }
    ]
  }
}
```

- `participantId` — server-assigned UUIDv4 (= peerId).
- `admissionIndex` — monotonic uint64 per SFU room, never reused.
- `transportId` — UUIDv4 for the participant's single SFU transport.
- `iceServers` — exactly the shape `RTCPeerConnection` expects;
  TURN credentials, when present, are short-lived per-server-policy
  values; the contract does not constrain their lifetime.

`from` is omitted on this server-originated message.

`roster_snapshot` follows immediately (§3.6).

---

### 3.3 `join_rejected` (S→C)

**Purpose**: typed pre-admission rejection.

```json
{
  "v": 3,
  "type": "join_rejected",
  "roomId": "demo",
  "requestId": "5b3a1e23-...",
  "payload": {
    "result": "join_rejected_room_full",
    "reason": "room_full",
    "message": "SFU room 'demo' already has 4 reserved participants."
  }
}
```

`payload.result ∈ { "join_rejected_room_full", "join_rejected_invalid_room" }`.

**Forbidden**: a bare `room_full` envelope `type` MUST NOT exist in v3.
Pre-admission rejection has exactly one canonical channel: this
message (mirrors v1 / v2 convention).

`unsupported_version` is **not** a `join_rejected` result; it is an
`error` (§3.21).

---

### 3.4 `leave_room` (C→S)

**Purpose**: explicit, graceful departure.

```json
{
  "v": 3,
  "type": "leave_room",
  "roomId": "demo",
  "payload": {}
}
```

**Server behavior**:

1. Release the leaver's slot (preserve `admissionIndex`, never
   reused).
2. Tear down forwarding legs (mediafabric `CloseTransport`).
3. Broadcast `participant_left { participantId, reason: "graceful_leave" }`
   to remaining participants.
4. For each affected SubscribedTrack on remaining participants, emit
   `subscribed_track_removed` (§3.13).
5. Close the leaver's WS.

---

### 3.5 `participant_left` (S→B)

**Purpose**: notify remaining participants that a peer has departed.

```json
{
  "v": 3,
  "type": "participant_left",
  "roomId": "demo",
  "payload": {
    "participantId": "8e4c0-...",
    "reason": "graceful_leave"
  }
}
```

`reason ∈ { "graceful_leave", "disconnect" }`.

`disconnect` covers WS-level pong-timeout (≤ 10 s) and any other
ungraceful close.

---

### 3.6 `roster_snapshot` (S→C)

**Purpose**: deliver the full current roster to a newly-admitted
participant. Sent **once**, immediately after `join_accepted`.

```json
{
  "v": 3,
  "type": "roster_snapshot",
  "roomId": "demo",
  "payload": {
    "serverSeq": 12,
    "participants": [
      { "participantId": "a11ce-...", "admissionIndex": 1, "presence": "media-ready" },
      { "participantId": "b0b00-...", "admissionIndex": 2, "presence": "media-ready" },
      { "participantId": "8e4c0-...", "admissionIndex": 3, "presence": "joined"      }
    ]
  }
}
```

- `serverSeq` — monotonic per SFU room; subsequent `roster_update`
  carries strictly greater values.
- `participants` — every participant in the room **including the
  newly-admitted client**.
- `presence ∈ { "joined", "media-ready", "released", "left" }`.
  (`released` and `left` typically do not appear in a snapshot
  because the participant is no longer in the room; included for
  schema completeness.)

---

### 3.7 `roster_update` (S→B)

**Purpose**: announce one participant's presence/readiness change to
all participants in the SFU room.

```json
{
  "v": 3,
  "type": "roster_update",
  "roomId": "demo",
  "payload": {
    "serverSeq": 17,
    "subjectParticipantId": "8e4c0-...",
    "admissionIndex": 3,
    "presence": "media-ready",
    "reason": "media_ready"
  }
}
```

`reason ∈ { "admitted", "media_ready", "media_failed", "graceful_leave",
"disconnect" }`.

Client validation: monotonic `serverSeq` (else `error stale_roster_update`).

---

### 3.8 `media_ready` (C→S)

**Purpose**: client reports successful local-media acquisition.

```json
{
  "v": 3,
  "type": "media_ready",
  "roomId": "demo",
  "payload": {
    "mediaCapabilities": { "audio": true, "video": true }
  }
}
```

Both `audio` and `video` MUST be `true` (SFU MVP has no observer
mode; FR-031, EC-001).

**Server behavior**: transition the participant `joined → media-ready`,
emit one `roster_update { presence: "media-ready", reason: "media_ready" }`
to all room participants. Mediafabric prepares to receive PublishedTracks
once the browser↔SFU transport reaches `connected`.

---

### 3.9 `media_failed` (C→S)

**Purpose**: client reports local-media acquisition failure. Triggers
slot release.

```json
{
  "v": 3,
  "type": "media_failed",
  "roomId": "demo",
  "payload": {
    "reason": "permission_denied",
    "detail": "camera_permission_denied"
  }
}
```

`reason ∈ { "permission_denied", "device_not_found", "device_in_use", "other" }`.

**Server behavior**:

1. Release the sender's slot (preserve `admissionIndex`).
2. Send `participant_released` to the sender (§3.10) with
   `result = "participant_released_media_failed"`.
3. Broadcast `roster_update { subjectParticipantId, presence: "released",
   reason: "media_failed" }` to remaining room participants.

---

### 3.10 `participant_released` (S→C)

**Purpose**: tell a previously-admitted client its **own** slot was
released without ever publishing media.

```json
{
  "v": 3,
  "type": "participant_released",
  "roomId": "demo",
  "payload": {
    "result": "participant_released_media_failed",
    "reason": "media_failed",
    "detail": "camera_permission_denied"
  }
}
```

`result ∈ { "participant_released_media_failed", "participant_released_disconnect" }`.

**Client behavior**: media-acquisition failure is **retry-able** via
reload / re-join. The MVP does NOT support a subscribe-only observer
mode (FR-031, EC-001, Non-Goals).

---

### 3.11 `transport_offer_requested` (S→C)

**Purpose**: ask the client to send an initial `transport_offer`. The
server MAY send this immediately after `media_ready` to make the
"server kicks the negotiation" relationship explicit, but the client
MAY also send `transport_offer` directly after `media_ready` without
waiting (the contract allows both shapes).

```json
{
  "v": 3,
  "type": "transport_offer_requested",
  "roomId": "demo",
  "payload": {
    "transportAttemptId": 1
  }
}
```

If sent, `transportAttemptId == 1` for the initial transport.

---

### 3.12 `transport_offer` (C→S)

**Purpose**: deliver the browser's SDP offer to the SFU.

```json
{
  "v": 3,
  "type": "transport_offer",
  "roomId": "demo",
  "payload": {
    "transportAttemptId": 1,
    "sdp": { "type": "offer", "sdp": "v=0\r\n..." }
  }
}
```

**Server validation**:

- Sender's `presence == media-ready`.
- `payload.transportAttemptId == server.currentAttemptId[transportId]`;
  if less, `error { code: "stale_transport_attempt", expected: <newAttempt> }`
  to the sender; the server does NOT process the offer.
- `payload.sdp.type === "offer"`.

A second `transport_offer` for the same `transportAttemptId` is
`unexpected_offer`.

---

### 3.13 `transport_answer` (S→C)

**Purpose**: deliver the SFU's SDP answer to the browser.

```json
{
  "v": 3,
  "type": "transport_answer",
  "roomId": "demo",
  "payload": {
    "transportAttemptId": 1,
    "sdp": { "type": "answer", "sdp": "v=0\r\n..." }
  }
}
```

**Client validation**: matches current `transportAttemptId`;
`payload.sdp.type === "answer"`.

---

### 3.14 `transport_ice_candidate` (C→S→C)

**Purpose**: relay one ICE candidate (or end-of-candidates) for the
browser↔SFU transport. The SFU's own ICE candidates flow S→C; the
browser's flow C→S→ (consumed by mediafabric, not relayed onward).

C→S form (browser → SFU):

```json
{
  "v": 3,
  "type": "transport_ice_candidate",
  "roomId": "demo",
  "payload": {
    "transportAttemptId": 1,
    "candidate": {
      "candidate": "candidate:1 1 UDP ...",
      "sdpMid": "0",
      "sdpMLineIndex": 0,
      "usernameFragment": "abcd1234"
    }
  }
}
```

S→C form (SFU → browser): identical shape; `from` is omitted (the SFU
is not a Participant).

**End-of-candidates**: `payload.candidate == null` signals trickle
complete. The empty-string form `payload.candidate.candidate == ""`
is **invalid** and must be rejected as `error { code: "malformed" }`
(same convention as v1/v2).

**Server validation**: `transportAttemptId` matches; payload schema
ok.

**Client validation**: on receive, either call `pc.addIceCandidate(...)`
if remote description is set, or buffer per `iceBuffer` rules.

---

### 3.15 `transport_renegotiation_needed` (S→C)

**Purpose**: server tells the browser to re-offer because subscriptions
are about to be added or removed.

```json
{
  "v": 3,
  "type": "transport_renegotiation_needed",
  "roomId": "demo",
  "payload": {
    "transportAttemptId": 2,
    "intent": "add_subscription",
    "additions": [
      {
        "subscribedTrackId": "s-1...",
        "originParticipantId": "a11ce-...",
        "originPublishedTrackId": "p-1...",
        "kind": "audio",
        "source": "microphone"
      },
      {
        "subscribedTrackId": "s-2...",
        "originParticipantId": "a11ce-...",
        "originPublishedTrackId": "p-2...",
        "kind": "video",
        "source": "camera"
      }
    ],
    "removals": []
  }
}
```

`intent ∈ { "add_subscription", "remove_subscription", "update" }`.
For `add_subscription`, `additions` is non-empty. For
`remove_subscription`, `removals` is non-empty (each entry has
`{ subscribedTrackId }`). For `update`, both arrays MAY be non-empty.

`transportAttemptId` is the server-authoritative new attempt; client
uses this value as its next `transport_offer` attempt.

---

### 3.16 `transport_state_update` (S→C)

**Purpose**: server-reported composite SFUTransport state (per A.6)
for the local participant only. Lets the client correlate its
browser-side Principle V states with the server's view.

```json
{
  "v": 3,
  "type": "transport_state_update",
  "roomId": "demo",
  "payload": {
    "transportAttemptId": 2,
    "state": "connected"
  }
}
```

`state ∈ { "new", "connecting", "connected", "disconnected", "failed", "closed" }`.

This is informational; the source-of-truth Principle V states (FR-022)
remain the browser's own `RTCPeerConnection` state.

---

### 3.17 `published_track_added` (S→B)

**Purpose**: announce that a participant has published a new track to
the SFU. The local participant receives this for their own publishes
(confirmation) and for every remote publisher's tracks.

```json
{
  "v": 3,
  "type": "published_track_added",
  "roomId": "demo",
  "payload": {
    "publishedTrackId": "p-1...",
    "participantId": "a11ce-...",
    "kind": "audio",
    "source": "microphone"
  }
}
```

A fully-publishing participant produces exactly two
`published_track_added` events per session (one audio + one video).
Screen-share does NOT emit a new `published_track_added`; instead it
emits a `media_state_update` with `source: "screen"` (FR-042,
DD-004 = A).

---

### 3.18 `published_track_removed` (S→B)

**Purpose**: announce that a published track has ended (e.g. camera
unplugged).

```json
{
  "v": 3,
  "type": "published_track_removed",
  "roomId": "demo",
  "payload": {
    "publishedTrackId": "p-1...",
    "participantId": "a11ce-...",
    "reason": "track_ended"
  }
}
```

`reason ∈ { "track_ended", "publisher_left", "publisher_failed" }`.

---

### 3.19 `subscribed_track_added` (S→C)

**Purpose**: tell the local subscriber that a forwarding leg is now
established for a remote published track.

```json
{
  "v": 3,
  "type": "subscribed_track_added",
  "roomId": "demo",
  "payload": {
    "subscribedTrackId": "s-1...",
    "originParticipantId": "a11ce-...",
    "originPublishedTrackId": "p-1...",
    "kind": "audio",
    "source": "microphone",
    "transceiverMid": "0"
  }
}
```

`transceiverMid` lets the client map the receiver to the
`SubscribedTrackId`.

---

### 3.20 `subscribed_track_removed` (S→C)

**Purpose**: tell the local subscriber that a forwarding leg is gone
(remote track ended, remote left, etc.).

```json
{
  "v": 3,
  "type": "subscribed_track_removed",
  "roomId": "demo",
  "payload": {
    "subscribedTrackId": "s-1...",
    "reason": "publisher_track_ended"
  }
}
```

`reason ∈ { "publisher_track_ended", "publisher_left", "subscription_failed", "local_leave" }`.

---

### 3.21 `subscription_state_changed` (S→C)

**Purpose**: report subscriber-side state transitions for a single
SubscribedTrack.

```json
{
  "v": 3,
  "type": "subscription_state_changed",
  "roomId": "demo",
  "payload": {
    "subscribedTrackId": "s-1...",
    "state": "subscribed"
  }
}
```

`state ∈ { "not-subscribed", "subscribing", "subscribed", "track-ended", "failed" }`.

---

### 3.22 `media_state_update` (C→S→B)

**Purpose**: announce a publisher's mute / camera / video-source state
change. Server fans out to all other participants.

**Direction**: C→S→B (server fan-out).

```json
{
  "v": 3,
  "type": "media_state_update",
  "roomId": "demo",
  "payload": {
    "participantId": "a11ce-...",
    "publishedTrackId": "p-2...",
    "kind": "video",
    "source": "screen",
    "muted": false
  }
}
```

Schema rules:

- `payload.participantId` is **required**.
- One of (`publishedTrackId`) or (no track scope = participant-level
  metadata) MUST be present:
  - **Track scope**: includes `publishedTrackId`, `kind` (mirror of the
    track's kind), and either `source` (for video source switches:
    `camera` / `screen` / `camera-off`) or `muted` (mic mute).
  - **Participant scope**: omits `publishedTrackId` and applies to the
    participant as a whole (reserved; MVP only uses track scope).
- `payload.transportAttemptId` MUST NOT be present. Inclusion is
  `malformed` (FR-090 (a) hard rule).
- `payload.subscribedTrackId` MUST NOT be present (subscriber-side
  reflections are derived locally from the upstream
  `media_state_update` matched against the receiver).

**Server behavior**:

1. Validate sender's `presence == media-ready`.
2. Validate the schema and the absence of `transportAttemptId`.
3. Set `from = sender.participantId`.
4. Fan out to every other participant in the room. The sender does
   NOT receive its own message back.
5. Do NOT log the values beyond a count + correlation ID.
6. Do NOT trigger any mediafabric Pion-level renegotiation.

**Forbidden**: client-side fan-out. Clients send exactly **one**
`media_state_update` per state change.

---

### 3.23 `sfu_status_changed` (S→B)

**Purpose**: room-level SFU media component availability broadcast.

```json
{
  "v": 3,
  "type": "sfu_status_changed",
  "roomId": "demo",
  "payload": {
    "status": "unavailable",
    "reason": "mediafabric_unavailable"
  }
}
```

`status ∈ { "available", "impaired", "unavailable" }`. The MVP UI
collapses `impaired` and `unavailable` into one room-level
"SFU unavailable" banner (FR-083 (a)).

The whole-process-down case (FR-083 (b)) does NOT use this message;
it surfaces as a client-side `signaling-error` from the WS close.

---

### 3.24 `forwarding_summary_update` (S→B)

**Purpose**: broadcast SFU-computed forwarding summaries used by the
cost summary panel and by the learning inspector forwarding section.

```json
{
  "v": 3,
  "type": "forwarding_summary_update",
  "roomId": "demo",
  "payload": {
    "serverSeq": 42,
    "publishedTracks": [
      {
        "publishedTrackId": "p-1...",
        "participantId": "a11ce-...",
        "kind": "audio",
        "source": "microphone",
        "subscriberDeliveryCount": 3,
        "subscriberOriginLabels": ["b0b00-...", "8e4c0-...", "k123-..."]
      },
      {
        "publishedTrackId": "p-2...",
        "participantId": "a11ce-...",
        "kind": "video",
        "source": "camera",
        "subscriberDeliveryCount": 3,
        "subscriberOriginLabels": ["b0b00-...", "8e4c0-...", "k123-..."]
      }
    ]
  }
}
```

`subscriberOriginLabels` are participant IDs (origin labels), not raw
SSRC values. Raw SSRC hex MUST NOT appear (NFR-004).

The message MAY be coalesced server-side to avoid spam; clients MUST
process it idempotently.

### 3.25 `learning_inspector_update` (S→C)

**Purpose**: deliver per-track inspector summaries (subscriber-side
view) that the client may not be able to derive on its own.

```json
{
  "v": 3,
  "type": "learning_inspector_update",
  "roomId": "demo",
  "payload": {
    "subscribedTracks": [
      {
        "subscribedTrackId": "s-1...",
        "originParticipantId": "a11ce-...",
        "kind": "audio",
        "source": "microphone"
      }
    ]
  }
}
```

Optional message: client renders summaries from this when present;
otherwise renders from its own slice state. No raw RTP / SDP / ICE
in the payload.

### 3.26 `error` (S→C or bidirectional)

**Purpose**: typed protocol-level error.

```json
{
  "v": 3,
  "type": "error",
  "payload": {
    "code": "stale_transport_attempt",
    "message": "Transport attempt 2 expected; got 1.",
    "correlates": "5b3a1e23-...",
    "context": { "transportId": "f7c11-...", "expected": 2, "observed": 1 }
  }
}
```

**Error codes**:

| Code | Meaning |
|---|---|
| `already_joined` | same WS tried to join two SFU rooms |
| `unsupported_version` | `v != 3` on `/ws/sfu` |
| `malformed` | envelope or payload failed schema validation (includes `transport_ice_candidate` with `candidate: ""`, includes `media_state_update` carrying `transportAttemptId`) |
| `not_in_room` | protocol action requires room membership |
| `unexpected_media_ready` | `media_ready` received while sender's presence is not `joined` |
| `unsupported_media_capability` | `media_ready.mediaCapabilities` missing `audio` or `video` |
| `unexpected_offer` | `transport_offer` while no offer was expected, or with wrong attempt id |
| `unexpected_answer` | `transport_answer` consumed without a matching outstanding offer (server-side check) |
| `stale_transport_attempt` | inbound transport-negotiation message's `transportAttemptId < server.currentAttemptId` |
| `stale_roster_update` | `serverSeq` was less than the previously-broadcast value (server invariant violation) |
| `internal_error` | server-side fault (no detail leaked) |

> **`room_full` and `invalid_room_id` are NOT `error` codes.**
> Pre-admission rejection is delivered exclusively via `join_rejected`
> (§3.3) with `payload.result` set accordingly.
>
> **`screen_share_busy` is NOT a code, NOT a message type.** The SFU
> has no room-level current-sharer concept (DD-004 = A; concurrent
> sharers allowed; FR-042).
>
> **No chat error codes.** Chat is omitted from SFU (DD-003 = A).

---

### 3.27 WebSocket-level Ping / Pong (out of band)

**Purpose**: ungraceful-disconnect detection (SC-S04).

- Server-initiated WS Ping frames (control frames, not JSON).
- Ping interval: `5 s`. Pong timeout: `5 s` after each Ping send.
- Worst case: ≤ `10 s` total.
- Configurable via `PING_INTERVAL_MS` / `PONG_TIMEOUT_MS` env vars
  (5000 ms defaults; shared with 001 / 002 server config).

Clients do NOT send app-level ping JSON. Browser auto-Pongs.

On Pong timeout:

1. Server closes the WS.
2. Server releases the leaver's slot (preserve `admissionIndex`).
3. Server emits `roster_update { presence: "left", reason: "disconnect" }`
   to remaining participants.
4. Server emits `participant_left { reason: "disconnect" }` to
   remaining participants if the leaver was past `media-ready`.
5. mediafabric closes the leaver's transport; forwarding legs torn
   down; remaining participants get `subscribed_track_removed` per
   leg.

## 4. Relay semantics

The SFU server is **not** a pure signaling relay (mesh mode was). For
SFU mode, the server **terminates** transport-negotiation messages on
its own Pion-based mediafabric:

- `transport_offer` (C→S): consumed by mediafabric; server replies
  with `transport_answer` (S→C).
- `transport_ice_candidate` (C→S): consumed by mediafabric.
- `transport_ice_candidate` (S→C): originated by mediafabric.
- `transport_answer`: never sent C→S in MVP (browser is always
  offerer; FR-090 / research §2). Reserved for future use.

For metadata fan-out (`media_state_update`):

1. Validate envelope + sender presence.
2. Set `from = sender.participantId`.
3. Forward the JSON to all other participants in the room (no
   modification of `payload`).
4. Do NOT log the value beyond a count + correlation ID.
5. Do NOT cache or persist.

For roster / participant-left / participant-released / sfu-status
broadcasts: server-originated; `from` is omitted.

## 6. Conformance checklist

A compliant SFU implementation MUST:

- [ ] Validate every inbound message against its schema in §3.
- [ ] Reject any message with `v != 3` on `/ws/sfu`
      (`error unsupported_version`).
- [ ] Use **one** pre-admission rejection message (`join_rejected`)
      and **one** post-admission release message
      (`participant_released`).
- [ ] Use **one** roster snapshot at admission (§3.6) and ordered
      `roster_update` messages thereafter (§3.7). No out-of-band
      roster channels.
- [ ] Carry `transportAttemptId` on every transport-negotiation
      message (offer, answer, ICE candidate, renegotiation
      instructions). Drop messages with stale `transportAttemptId`
      and log peer-scoped.
- [ ] **Never** carry `transportAttemptId` on `media_state_update`,
      `published_track_*`, `subscribed_track_*`,
      `subscription_state_changed`, `forwarding_summary_update`,
      `learning_inspector_update`, `roster_*`, `participant_left`,
      `participant_released`, or `sfu_status_changed`.
- [ ] Forward `transport_ice_candidate` end-of-candidates as
      `candidate: null` exactly. Reject `candidate: ""` as
      `malformed` (mirror v1/v2 convention).
- [ ] Send a `media_state_update` on every local mute / camera
      toggle / video-source switch. **Server fan-out** to all other
      participants — clients MUST send exactly one signaling message
      per state change.
- [ ] Refuse to create the browser `RTCPeerConnection` and emit
      `transport_offer` before `media_ready`.
- [ ] Browser is always offerer; server never sends `transport_offer`
      in MVP.
- [ ] On a remote `participant_left`, **keep local
      `MediaStreamTrack`s running** — only the remote left. Drop the
      affected SubscribedTracks.
- [ ] Reject `media_ready` payloads where either `audio` or `video`
      is not `true` (no observer mode, FR-031).
- [ ] On WS-level Pong timeout, close the WS within the configured
      window (default 5 s after Ping; ≤ 10 s total).
- [ ] **Never** introduce a `screen_share_busy` (or equivalent)
      message or error code (DD-004 = A).
- [ ] **Never** introduce a chat message type or chat error code
      (DD-003 = A).
- [ ] Maintain `admissionIndex` monotonic and **never reused** within
      an SFU room's lifetime.
- [ ] **Never** log SDP bodies, ICE candidate strings, raw SSRC hex,
      raw RTP payloads, or TURN credentials (NFR-004, SC-S08).
- [ ] **Never** persist or record media. mediafabric forwards only
      (NFR-003, SC-S07).
- [ ] Emit `sfu_status_changed { status: "unavailable" }` only when
      the signaling/control plane is alive; whole-process-down is
      surfaced as a client-side `signaling-error` from WS close
      (FR-083 (a) vs (b)).
- [ ] Never claim end-to-end encryption of SFU media (Principle VII,
      NFR-003).
- [ ] Omit envelope `from` on system-originated S→C/S→B messages
      (`join_accepted`, `join_rejected`, `roster_*`,
      `participant_*`, `transport_*`, `published_track_*`,
      `subscribed_track_*`, `subscription_state_changed`,
      `sfu_status_changed`, `forwarding_summary_update`,
      `learning_inspector_update`). Carry `from = sender.participantId`
      only on relay messages (`media_state_update`).

## 7. Versioning & evolution

- The SFU contract is `v: 3`. Any future incompatible change to the
  SFU contract MUST be issued as `v: 4` (or namespaced subtype) to
  preserve in-flight clients.
- Additive evolution rule: new optional fields on existing types are
  permitted as long as both sides can ignore them; new message types
  require a contract revision PR.
- Cross-mode compatibility: v1 (001), v2 (002), and v3 (003) coexist
  by living on different endpoints (`/ws`, `/ws/mesh`, `/ws/sfu`).
  They MUST NOT share message types.
